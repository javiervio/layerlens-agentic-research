## Top 3 bets

Ranked by `features/matrix.csv` Priority (Impact x Confidence / Effort), current as of this run.

### 1. F-0005 — Flag same-family judge/agent pairings (Priority 1.80, Impact 3, Effort 1, Confidence 0.6, L1)

**Full evidence chain**: source -> claim -> pain point -> idea -> feature.
- Sources: ["The Judge in the Mirror"](https://github.com/hankimis/self-preference) (pilot, 4 models, 2 families, mean self-preference index +0.14) -> **C-0002**. ["LLMs Trust Their Own"](https://arxiv.org/abs/2609.33495) (12 open-weight models, 9 tasks, independent authors/method) -> **C-0014**, the second independent family that promoted this to **thesis T-05**. ["Reliability without Validity"](https://arxiv.org/abs/2606.19544) (21 judges, 9 providers, ~541,000 judgments: "the most reproducible judges are among the least valid") -> **C-0027**, a third, larger-scale family.
- Pain point: an AI judge quietly favors its own model family; verdicts are biased with no visible signal to the user.
- Idea: **I-0005** (flag same-family judge/agent pairings), L1.
- Feature: **F-0005**, cheap to build (Effort 1: metadata comparison + a UI badge), currently the single highest-priority row in the matrix.
- Decision: **build-ready pending a product check.** The evidence bar is unusually strong for an Effort-1 feature. The one blocking step is confirming whether LayerLens's UI today even surfaces which model a Judge/Scorer runs versus which model the agent-under-test runs — if that metadata already exists, this is close to a pure UI/copy change.
- **Why now**: three independent research groups, different methods, same direction, zero counter-evidence; this is as close to a settled finding as this knowledge base has produced, and the fix is cheap.

### 2. F-0003 — Always show a tradeoff axis (cost or reliability) beside the primary score (Priority 1.20, Impact 4, Effort 2, Confidence 0.6, L1)

**Full evidence chain**:
- Sources: [tau2-bench v1.0.1 release notes](https://github.com/sierra-research/tau2-bench/releases) (a maintainer had to declare scores non-comparable across a grading-fix version) -> **C-0003**. [HAL / Holistic Agent Leaderboard](https://github.com/princeton-pli/hal-harness) (Princeton PLI; cost-blind leaderboards are uninformative; a cost-accuracy Pareto frontier instead of a single rank; project since archived, team pivoted to reliability work) -> **C-0009**.
- Pain point: a 1-point accuracy edge can hide a 10x cost difference; single-number rankings mislead.
- Idea: **I-0004**, L1.
- Feature: **F-0003**. Mostly surfaces data the platform already has (cost from real usage); HAL is a concrete reference design for the comparison view.
- Decision: **build-ready pending a product check** (does the current comparison view show cost/reliability by default today?).
- **Why now**: a credible, highly-cited lab (Princeton PLI) built the Pareto-frontier version of this and then explicitly archived it to go pursue reliability work instead — evidence that comparability infrastructure was table stakes for them, not their differentiator. For LayerLens, always showing a tradeoff axis is a low-effort way to clear that same table-stakes bar before competitors do.

### 3. F-0001 — pass^k reliability readout + adaptive run-count recommendation (Priority 1.00, Impact 4, Effort 3, Confidence 0.75, L1, evidence-complete)

**Full evidence chain**:
- Sources: ["Towards a Science of AI Agent Reliability"](https://arxiv.org/abs/2602.16666) (Princeton, ICML 2026; pass@k vs pass^k vocabulary; "reliability shows minimal improvement... despite 24 months of model releases") -> **C-0008**. ["Same Winners, Different Success Rates"](https://arxiv.org/abs/2609.34215) (ordinal benchmarks provably hide reliability) -> **C-0013**. ["Identical Runs, Different Results"](https://arxiv.org/abs/2609.33812) (584 real coding-agent runs: run-to-run variance exceeds agent-to-agent difference) -> **C-0019**, a third, real-world family.
- Pain point: a single pass/accuracy number hides whether an agent behaves the same way twice.
- Idea: **I-0001**, L1, flagged evidence-complete.
- Feature: **F-0001**.
- Decision: **the single fastest lever in the whole backlog** — this idea needs no more external corroboration (three independent families, one from real-world benchmarking, not an academic proposal); it is blocked purely on a ~15-30 minute product check (do Runs/Insights show reliability today?) that this research agent cannot perform itself.
- **Why now**: deterministic, free re-minting is a LayerLens-specific economic advantage here — k-repeat reliability testing is nearly free for LayerLens in a way it is not for a paid or stateful competitor sandbox, so this is a moat-aligned feature, not a generic one. Build caution: C-0024 ("Beyond Pass@k") shows some benchmarks compute pass@k wrong by conflating sub-task checks with independent rollouts — whatever "k attempts" means here must be genuinely independent full-task runs.

## Cross-cutting design principles the corpus now supports

1. **Deterministic grading is a moat, not a legacy choice.** Three independent studies (T-05: C-0002, C-0014, C-0027) now document that LLM judges carry structural, identity-linked bias, and that a judge's own re-run consistency does not imply its correctness ("the most reproducible judges are among the least valid," C-0027). This is not an argument against Judges/Scorers as a category — it is an argument for never treating them as a drop-in replacement for an answer-key Grader, and for exposing (not hiding) a Judge's own confidence and potential same-family bias wherever it is used.

2. **Attribution must be built in, not audited in.** Nine evidence families now populate thesis T-02, and this quarter's newest (BenchShield, C-0039) marks a shift in the pattern itself: earlier sources (BenchJack, HackDetect) are reactive audits of benchmarks that already shipped; BenchShield instruments the evaluation infrastructure prospectively. That is structurally the same move LayerLens's own trust wall already makes (seed/knobs never served to an agent-facing key, decided at design time, not bolted on after a problem is found). The market is converging on LayerLens's own architectural instinct here, which is validation, not a new mandate.

3. **Compete on legible, verified recovery — not on recovery mechanics.** Ten evidence families now populate T-06, and this quarter's newest three (Crab, DeltaBox, ACRFence) sharpen the cluster into a clean split: checkpoint/rollback/fork over **local sandbox state** is maturing toward commodity (Crab: 100% recovery correctness vs. 8-42% baselines; DeltaBox: 14ms/5ms latency) across at least four independent teams. Checkpoint/rollback over **remote/external state** — a CRM write, a payment, a consumed approval token — is not solved anywhere in this corpus, and ACRFence now demonstrates concrete, named attacks (Action Replay, Authority Resurrection) against exactly that gap. This is precisely LayerLens's own system-type shape (Salesforce, Linear, SEC EDGAR, Stripe, Gmail). The design principle: do not compete on building checkpoint/restore infrastructure (it is commoditizing, and several teams already do it well); compete on making recovery over *real, remote, external systems* legible and demonstrably safe, which nobody else in this corpus has done.

## Positioning ammunition (evidence-backed, externally usable)

- "Independent audits have found that major agent benchmarks — including SWE-bench Verified, WebArena, GAIA, and others — can be passed without the agent genuinely solving the task, in as many as 6 of 8 (BenchJack) and roughly two-thirds of audited trace families (HackDetect)." [C-0001, C-0006]
- "LLM judges measurably favor outputs from their own model family, a finding now independently replicated three times across different methods and model sets — which is why LayerLens keeps deterministic, answer-key grading load-bearing rather than delegating trust entirely to an AI judge." [C-0002, C-0014, C-0027]
- "A widely-used, actively-maintained agent benchmark (tau2-bench) had to publicly declare its own scores non-comparable across a grading-bug fix — a real, dated example of exactly the versioning problem LayerLens's immutable environment/task/grader versions are built to make structurally impossible, not something a maintainer has to remember to announce." [C-0003]
- "Checkpoint/rollback for agent sandboxes is fast becoming a commodity capability (recent published work reaches 100% recovery correctness and millisecond-level latency) — but naive rollback can actively cause harm on real external systems, with named, demonstrated attack classes (duplicate payments, resurrected one-time authorizations) already published. Any product offering 'undo' over real business systems needs to design for this explicitly; LayerLens's system-type model (Salesforce, Stripe, Linear, Gmail, SEC EDGAR) means this is not a hypothetical concern for us." [C-0037, C-0038, C-0026]
